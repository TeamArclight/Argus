# Contributing to ARGUS

- Never work directly on `main`.
- Create short-lived feature branches, for example:
  - `frontend/dashboard`
  - `backend/tender-api`
  - `ai/tender-extraction`
- Create pull requests for all changes.
- Keep PRs small and reviewable.
- Update shared contracts when API structures change.
- Do not modify another developer's owned area without coordination.

Recommended flow:

feature branch
→ pull request
→ review
→ main
